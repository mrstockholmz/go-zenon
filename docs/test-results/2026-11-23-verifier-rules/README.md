# Verifier-rule cases (B-6 series, V series) — 2026-11-23

Branch `test/verifier-cases` (stacked on `test/spork-cases`). Node image
`go-zenon-devnet:latest`, driver on the host from the branch head.
Network: five nodes on the `staged` genesis (libp2p 20, dynamic-plasma 30,
ptlc 60, embedded-refund 70, epoch-reward-terms 80), published on host ports
37991-37997 so the mainnet (3599x) and L6 (3699x) nodes keep theirs.

## What was added

`test/e2e/verifierrules_test.go`:

- `TestVerifierAccountRules` / B-6 series — negative cases for the
  account-block verifier rules the B-series did not reach:
  - B-6a send-side amount fields: negative amount (`ErrABAmountNegative`),
    amount with zero token standard (`ErrABZtsMissing`), from-block-hash set
    on a send (`ErrABFromBlockHashMustBeZero`) — rule `account_block.amounts`.
  - B-6b momentum-acknowledged gap: block acking an older momentum than the
    account's previous block (`ErrABMAGap`) — `account_block.momentumAcknowledged`.
  - B-6c receive block carrying data after the Dynamic Plasma spork
    (`ErrABDataMustBeEmpty`) — `account_block.receiveData` and its gate
    `account_block.isDynamicPlasmaActiveAtMA` (E7).
  - B-6d forged embedded receives for the plasma contract. The forgeries
    race the producer's auto-receive generator, so each case pre-builds the
    forged block and fires it with a single RPC once the send confirms
    (the pool's sequencer state advances as auto-receive gossip arrives,
    well inside one momentum period — measured with a mailbox probe):
    - B-6d1 receive of a send that is queued behind another
      (`ErrABSequencerNotNext`) — `account_block.sequencer`.
    - B-6d2 forged receive carrying base plasma (a hash-excluded field)
      under an honest hash: refused by the VM's auto-receive regeneration
      (`ErrAutoReceiveChangesHashMismatch`) before the transaction-level
      `plasmaFields` rule is reached — see "Not covered" below.
    - B-6d3 forged receive acknowledging the momentum before the one that
      confirmed its send (`ErrABMAInvalidForAutoGenerated`), a block-level
      rule refused before any execution.
  - B-6e descendant blocks on a user send (`ErrABDescendantMustBeZero`) —
    `account_block.descendantBlocks`. Reaching the rule needs a well-formed
    batch: `block.Previous()` reports the previous of the FIRST descendant,
    so the child chains onto the real account frontier and the head sits one
    above it; a malformed batch dies earlier, in `getContext` ("previous
    block is missing" — confirmed with an instrumented debug build: a
    height-1 batch head underflows `Previous()` to height 2^64-1).
  - B-6f chain-untouched control after the refusals.
- `TestVerifierMomentumRules` — positive assertions over RPC for the
  momentum-side rules (V-1: 30-momentum walk re-checking chain identifier,
  version, timestamps strictly increasing, previous-hash links, empty data,
  resource prices, pillar producers by `producerAddress`, content
  resolution; V-2: content blocks' acknowledgements sit at or above the
  highest enforced spork; V-3: the dynamic-plasma format boundary read back
  from history at enf-1/enf/enf+1 — version 1, 1, 2).

`test/e2e/ledger_test.go`: the B-series subtests that already exercised
verifier rules now also record the rule rows (previously only the `error`
rows were covered): version, blockType, chainIdentifier, amounts, pow,
previous, momentumAcknowledged, fromHash, signature, producer, hash, and the
happy-path pipeline (all/getContext/verifyTransaction).

`test/e2e/sporkstaged_test.go`: records `momentum.version`,
`momentum.nextFusionPrice`, `momentum.nextWorkPrice` at the boundaries the
S-1/S-2 subtests already assert.

## Not covered (stated, not hidden)

- `account_block.plasmaFields` and the embedded arms of
  `account_block.signature` (`ErrABPublicKeyMustBeZero` /
  `ErrABSignatureMustBeZero`): on the publish path the VM re-generates every
  contract receive and compares the changes-hash and the block hash BEFORE
  the transaction verifier runs (`Supervisor.applyBlockWith` order:
  block-level rules → `vm.applyBlock` → transaction-level rules). A forged
  receive with any wrong hashed field dies at that wall; a forged receive
  that passes it must carry a contract-execution-computed changes-hash,
  which a black-box client cannot produce. These arms are covered by unit
  tests (`vm/embedded/tests/zz_sec_descendant_test.go` drives
  `ErrABPlasmaMustBeZero` directly); the e2e suite covers the wall itself
  (B-6d2, `ErrAutoReceiveChangesHashMismatch`).
- `momentum.changesHash` and `momentum.contentByteBound` negative arms need
  producer-side fault injection (a forged momentum reaching an honest node).
  V-2 covers `momentum.acknowledgementRecency` positively on live content.
- `account_block`'s embedded-only `ErrABSequencerNothing` (the mailbox
  empties itself one momentum after any send confirms, so no external block
  can observe the empty state).

## How to reproduce

```sh
test/devnet/build-image.sh            # or make devnet-up for the stock image
test/devnet/up.sh staged               # five nodes on the staged genesis
E2E_RPC=http://localhost:35997,http://localhost:35991 \
E2E_CHAIN_ID=69 E2E_MIN_HEIGHT=12 \
E2E_COVERAGE=$PWD/docs/test-results/2026-11-23-verifier-rules/coverage.tsv \
  go test -tags e2e -v -timeout 30m ./test/e2e/ -run 'TestSporkStagedEnforcement'
# after the chain passes the last staged height:
E2E_RPC=http://localhost:35997,http://localhost:35991 \
E2E_CHAIN_ID=69 \
E2E_COVERAGE=$PWD/docs/test-results/2026-11-23-verifier-rules/coverage.tsv \
  go test -tags e2e -v -timeout 30m ./test/e2e/ \
  -run 'TestLedger|TestVerifierAccountRules|TestVerifierMomentumRules'
test/inventory/record.py docs/test-results/2026-11-23-verifier-rules/coverage.tsv
test/inventory/check.sh
```

(The 30 m timeout is not generous: the staged crossing alone is ~12 min of
momentums. The default 10 m `go test` timeout kills the suite at the
ptlc/embedded-refund boundary. B-6d's races can eat minutes of retries on a
slow or contended devnet; the per-case deadline is 2 min.)
